# Frontend implementation review

Date: 2026-09-20  
Status: **IN PROGRESS — NOT PASSED**

## Scope and evidence

- React 19 + TypeScript + Vite; no Next.js. Routes are `/`, `/signin`, `/problems`, `/problem/:problemId`, `/result/:submissionId`, `/dashboard`, `/settings`, and `/notices`.
- Shared theme/components live under `frontend/src/design-system/`. Light/dark semantic tokens use gray surfaces and Kikyō `#5654A2`; ER relation/status colors are separate. External Google Fonts were removed so the build has no font-network dependency.
- Typed client uses the `/v1` contract for session, OAuth entry, onboarding, profile, account export/delete, problems/filtering, drafts, submissions, feedback/jobs, dashboard, posts/reports, notices, and translations. Mutations send CSRF and idempotency headers; API HTML/invalid responses fail visibly instead of rendering fake success.
- ER editor now has GUI table/column editing, relationship creation/cardinality editing, Mermaid/DDL/DBML serializers and parsers sharing the canonical model, invalid-source preservation, static diagnostics, manual placement, keyboard delete/undo/submit, and explicit ELK Arrange. DDL foreign keys and DBML/Mermaid references are represented as canonical relationships.
- Browser cache uses account-scoped IndexedDB drafts/details/problem summaries and durable queued submissions. Queue records retain the operation id and are retried on initial authenticated load and reconnect. Local cached problem details are used when the API is unavailable.
- PWA output is generated by `vite-plugin-pwa` with manifest metadata, `sw.js`, Workbox precache, and root navigation fallback. Authenticated API responses are not included in the precache.
- `.DS_Store` files were removed from `frontend/` and `docs/`.
